% ==================== 一、项目概述 ====================
\section{项目概述}

\subsection{项目背景}

随着企业信息化建设不断深入，中小企业对网络系统的依赖程度日益提高。企业内部办公自动化（OA）、邮件通信、文件共享、远程办公以及互联网访问等业务均需要稳定、安全、高效的网络环境作为支撑。

本项目针对某中小企业进行网络规划与设计。企业总部拥有约 1000 台 PC，并设有市场部、财务部、人事部、研发部、行政部、运营部、客服部共 7 个部门，同时在外省设有 3 个分公司。企业要求实现总部与分公司的互联互通，并能够安全地对外提供 WEB、邮件以及匿名 FTP 服务，同时保障内部 OA 系统的正常运行。

本方案基于 Cisco Packet Tracer 平台，采用\textbf{Hub-and-Spoke（中心辐射型）}网络拓扑架构，以中心路由器为核心，通过高速串行链路连接 ISP、分公司及总部网络。网络采用 \textbf{RIPv2 动态路由协议}实现路由自动学习，结合 \textbf{VLAN、ACL、VPN（IPSec）、NAT、DHCP} 等关键网络技术，构建安全、可靠、可扩展的企业网络环境。

\subsection{项目需求}

根据题目要求，网络系统需满足以下需求：

\begin{enumerate}[label=(\arabic*), leftmargin=2em]
    \item 公司总部拥有约 1000 台 PC；
    \item 企业共有 7 个部门，不同部门之间访问权限受限；
    \item 企业拥有 3 个跨省分公司；
    \item 企业内部部署 OA 系统；
    \item 企业可对外提供 WWW、匿名 FTP、邮件服务；
    \item FTP 服务仅允许内部员工访问；
    \item 所有终端均可访问互联网；
    \item 每个部门独立划分 VLAN；
    \item 总部与分公司之间通过 VPN 技术实现安全互联；
    \item 支持远程办公人员通过 VPN 接入企业内网；
    \item 网络需具备较高安全性、可靠性与扩展能力。
\end{enumerate}

% ==================== 二、可行性分析报告 ====================
\section{可行性分析报告}

\subsection{社会可行性分析}

企业信息化网络建设能够显著提升企业办公效率，促进企业内部信息共享与资源协同。通过构建统一的企业网络平台，可以实现跨部门协作、远程办公、数据共享以及业务系统集中管理。

VPN 技术能够有效保障总部与分公司之间的数据传输安全，提高企业跨区域协同办公能力。同时，通过建设 OA 系统与内部服务器平台，企业能够进一步提升管理效率，降低运营成本。

本方案新增了对\textbf{远程办公人员 VPN 接入}的支持，使外部员工能够通过加密隧道安全访问企业 OA 系统和内部资源，符合后疫情时代混合办公模式的社会需求。

因此，本项目具有较高的社会应用价值和现实意义。

\subsection{技术可行性分析}

本系统主要采用 \textbf{VLAN、VPN（IPSec）、ACL、RIPv2、NAT、DHCP、STP} 等成熟网络技术，具备较高的技术可行性。

\subsubsection{VLAN（虚拟局域网）}

VLAN 技术能够将不同部门划分为独立广播域，实现逻辑隔离，减少广播风暴，提高网络安全性与管理效率。本方案中，总部通过核心交换机 2560-24PS 划分 VLAN，各分公司通过路由器子接口实现 VLAN 隔离。

\subsubsection{VPN（虚拟专用网络）}

VPN 技术用于实现总部与外省分公司之间的安全通信，以及远程办公人员的安全接入。

本方案采用 \textbf{IPSec VPN} 技术，包括：
\begin{itemize}
    \item \textbf{站点到站点 VPN（Site-to-Site VPN）}：总部与三个分公司之间建立 IPSec 隧道，保证跨公网的数据加密传输；
    \item \textbf{远程访问 VPN（Remote Access VPN）}：外部办公 PC 通过 VPN 服务器接入企业内网，安全访问 OA 系统和内部资源。
\end{itemize}

\subsubsection{RIPv2（路由信息协议第二版）}

RIPv2 是一种经典的距离矢量路由协议，支持 VLSM 和 CIDR，适用于中小型网络的动态路由学习。本方案在总部、分公司和 ISP 之间的路由器上部署 RIPv2，实现全网路由自动学习与通告，保证内网可达性。

\subsubsection{ACL（访问控制列表）}

ACL 用于实现精细化的访问控制策略：
\begin{itemize}
    \item 禁止普通部门（如市场部）访问财务部 VLAN；
    \item 仅允许内部员工通过 FTP 协议访问 FTP 服务器；
    \item 限制外部网络对内部 OA 系统的直接访问；
    \item 控制 VPN 流量的加密范围。
\end{itemize}

\subsubsection{NAT（网络地址转换）}

NAT 技术实现内部私有 IP 地址到公网 IP 地址的转换。本方案在 ISP 边界路由器上配置 PAT（端口地址转换），使所有内部终端共享一个公网 IP 地址访问互联网，同时隐藏内部网络拓扑，提高安全性。

\subsubsection{DHCP（动态主机配置协议）}

DHCP 服务器自动为各 VLAN 的终端分配 IP 地址、默认网关和 DNS 服务器地址。本方案将 DHCP 服务与 DNS 服务部署在同一台服务器上（IP: 192.168.80.50），减少人工配置工作量，降低 IP 地址冲突风险。

\subsubsection{STP（生成树协议）}

STP 用于防止交换网络中的环路问题。在总部核心交换机与部门接入交换机之间运行 STP，避免二层环路导致的广播风暴，提高网络稳定性。

\subsection{业务流量与访问关系分析}

在进行具体网络设备配置之前，需要先明确企业内部各类业务系统的访问路径。中小企业网络虽然规模小于大型园区网，但其业务类型较完整，既包含普通办公终端的互联网访问，也包含跨部门访问、服务器区访问、分公司接入以及远程办公接入等多类流量。如果在设计阶段没有区分业务流量类型，后续 ACL、NAT、VPN 和路由策略容易出现规则重叠或控制粒度不足的问题。

本方案将企业流量划分为以下六类：

\begin{enumerate}[label=(\arabic*), leftmargin=2em]
    \item \textbf{部门内部流量}：同一 VLAN 内终端之间的文件共享、打印、局域网协作等，主要在二层交换网络内转发；
    \item \textbf{部门间流量}：不同 VLAN 之间的业务访问，需要经过三层网关转发，并受 ACL 策略控制；
    \item \textbf{用户到服务器区流量}：各部门访问 OA、DNS、DHCP、Web、Email、FTP 等服务，属于最核心的内部业务流量；
    \item \textbf{分公司到总部流量}：分公司终端通过站点到站点 VPN 访问总部服务器区和必要的业务系统；
    \item \textbf{内网到互联网流量}：所有内部私有地址通过 NAT/PAT 转换后访问外部网络；
    \item \textbf{远程办公流量}：外部员工通过远程访问 VPN 获取虚拟内网地址，再访问总部内部资源。
\end{enumerate}

上述流量的控制原则为：部门内部默认允许；部门之间按照最小权限开放；服务器区只开放必要端口；FTP 服务只允许内网访问；远程办公用户必须先建立 VPN 隧道；外部互联网不能直接访问 OA 和内部 FTP 服务。通过这种方式，可以在满足业务连通性的同时降低横向移动和非法访问风险。

\subsection{地址容量与可扩展性分析}

总部约 1000 台 PC 分布在 7 个部门中。每个部门使用 /24 子网可以提供 254 个可用地址。若平均分配，每个部门约 143 台终端，/24 子网能够满足当前容量；若某些部门终端数量较多，也可以通过新增 VLAN 或将部门拆分为多个楼层 VLAN 的方式扩展。

本方案为每个部门预留了独立网段，避免所有终端集中在同一个大广播域中。这样做的好处包括：第一，广播报文被限制在本部门 VLAN 内，减少无效流量；第二，部门网关地址固定，便于 DHCP 地址池和 ACL 策略编写；第三，后续扩容时可以按部门或楼层逐步增加接入交换机，不需要重构全网地址规划。

\subsection{逻辑拓扑与物理拓扑对应关系}

在 Packet Tracer 仿真中，拓扑图表现的是设备和连线；在实际工程中，还需要考虑机房、弱电间、楼层、链路介质和故障域。本方案将逻辑拓扑与物理部署对应如下：

\begin{itemize}
    \item \textbf{中心机房}：放置核心路由器、总部顶级路由器、总部核心交换机和服务器接入交换机，是全网核心区域；
    \item \textbf{楼层弱电间}：放置部门接入交换机，使用光纤或六类线缆上联核心交换机；
    \item \textbf{分公司机房}：每个分公司部署一台边界路由器和一台接入交换机，通过公网链路与总部建立 VPN；
    \item \textbf{ISP 接入点}：连接企业出口路由器，为企业提供公网访问、远程办公入口和外部测试环境。
\end{itemize}

逻辑拓扑和物理拓扑分离的好处在于：网络管理员可以在不改变部门逻辑结构的情况下迁移物理终端。例如客服部从二楼迁移到三楼时，只需调整接入交换机端口所属 VLAN，而不需要修改 IP 地址规划、路由协议或服务器策略。

\section{网络结构设计}

\subsection{网络拓扑结构}

本方案采用 \textbf{Hub-and-Spoke（中心辐射型）}网络拓扑架构，以总部核心路由器（Core-Router，Cisco 2811）为整个网络的枢纽中心。拓扑结构分为以下层次：

\subsubsection{第一层：ISP 互联层}

ISP 采用 Cisco 2811 路由器，通过串行链路连接核心路由器。ISP 路由器同时连接外部 Web 服务器（模拟互联网服务）和外部测试 PC，用于验证外网访问功能。

\subsubsection{第二层：核心路由层}

核心路由器（Cisco 2811）是整个网络的交通枢纽，负责：
\begin{itemize}
    \item 向上通过串行链路连接 ISP，实现互联网接入；
    \item 向下连接总部顶级路由器（HQ-Router，Cisco 2811）；
    \item 通过三条串行链路分别连接三个分公司路由器，实现分支机构互联；
    \item 运行 RIPv2 动态路由协议，维护全网路由表。
\end{itemize}

\subsubsection{第三层：总部分发层}

总部网络采用两级结构：
\begin{itemize}
    \item \textbf{总部顶级路由器（HQ-Router，Cisco 2811）}：作为总部网络的网关，向上连接核心路由器，向下连接总部核心交换机。
    \item \textbf{总部核心交换机（HQ-Core-SW，Cisco 2560-24PS）}：作为总部网络的核心交换节点，通过 Trunk 链路连接各部门接入交换机和服务器区交换机，支持 VLAN 间路由。
\end{itemize}

\subsubsection{第四层：接入层}

\begin{itemize}
    \item \textbf{部门接入交换机（3 台 Cisco 2960）}：分别连接各部门 PC，承载 VLAN 10--70 的用户流量；
    \item \textbf{服务器接入交换机（1 台 Cisco 2960）}：连接服务器区三台服务器（VLAN 80）；
    \item \textbf{分公司交换机（3 台 Cisco 1960-24TT）}：各分公司内部的二层交换设备，连接分公司终端。
\end{itemize}

\subsubsection{第五层：分支机构}

每个分公司采用\textbf{二级路由结构}：
\begin{itemize}
    \item \textbf{分公司路由器（Cisco 2811）}：通过串行链路与总部核心路由器互联，运行 RIPv2，支持 IPSec VPN 隧道，通过子接口实现 VLAN 划分；
    \item \textbf{分公司交换机（Cisco 1960-24TT）}：连接分公司内部 PC 和终端设备。
\end{itemize}

\subsection{VPN 结构设计}

本方案采用双重 VPN 架构，满足不同场景的安全接入需求：

\subsubsection{站点到站点 IPSec VPN}

总部核心路由器与三个分公司路由器之间建立 IPSec VPN 隧道，实现以下功能：
\begin{itemize}
    \item 分公司终端可以安全访问总部的 OA 系统、文件服务器和内部资源；
    \item 所有跨公网传输的数据经过 AES 加密和 SHA 完整性校验；
    \item 使用预共享密钥（Pre-Shared Key）进行身份认证。
\end{itemize}

VPN 对等体关系如下：

\begin{center}
\begin{tabular}{c}
Branch1-Router $\longleftrightarrow$ Core-Router (IPSec Tunnel) \\
Branch2-Router $\longleftrightarrow$ Core-Router (IPSec Tunnel) \\
Branch3-Router $\longleftrightarrow$ Core-Router (IPSec Tunnel) \\
\end{tabular}
\end{center}

\subsubsection{远程访问 VPN}

ISP 侧的外部 PC 通过 VPN 客户端软件，经过公网连接到 VPN 服务器（ISP 路由器上配置），建立加密隧道后安全访问企业内部资源（如 OA 系统）。这是典型的\textbf{Remote Access VPN} 场景，满足远程办公需求。


\subsection{安全设计}

网络安全是本次设计的核心关注点。本方案采用多层次、纵深防御的安全体系：

\begin{enumerate}[label=(\arabic*), leftmargin=2em]
    \item \textbf{VLAN 逻辑隔离}：将不同部门划分到不同的广播域，实现二层隔离，防止部门间的非授权二层访问；
    \item \textbf{ACL 访问控制}：
        \begin{itemize}
            \item 在核心交换机上配置扩展 ACL，禁止普通部门（如市场部、客服部）访问财务部 VLAN 20；
            \item 在服务器区入口配置 ACL，仅允许内部 IP 地址段（192.168.0.0/16）访问 FTP 服务；
            \item 限制外部网络对 OA 系统（TCP 8080）的直接访问，仅允许 VPN 隧道流量通过。
        \end{itemize}
    \item \textbf{NAT 地址转换}：在 ISP 边界路由器上配置 PAT，隐藏内部网络结构，仅暴露一个公网 IP；
    \item \textbf{IPSec VPN 加密}：所有跨公网的站点间和远程接入流量均经过 IPSec 加密，防止数据窃听和篡改；
    \item \textbf{STP 环路防护}：在总部二层交换网络中启用生成树协议，防止广播风暴和 MAC 地址表震荡；
    \item \textbf{路由安全}：RIPv2 支持 MD5 认证（可在后续升级中启用），防止路由欺骗。
\end{enumerate}

\subsection{路由设计深化}

本方案选择 RIPv2 作为全网动态路由协议。虽然 RIPv2 的最大跳数限制为 15 跳，不适合大型复杂网络，但对于本项目的 Hub-and-Spoke 架构而言，总部、ISP 与三个分公司之间的路由层级较少，网络规模可控，RIPv2 的配置简单性和可读性更符合课程设计与中小企业运维场景。

\subsubsection{RIPv2 与静态路由对比}

如果全部使用静态路由，每新增一个分公司或服务器网段，都需要在多台路由器上手动添加回程路由。随着网络扩展，静态路由维护成本会快速上升，并且容易出现遗漏。RIPv2 能够自动学习各网段，降低配置复杂度。

\begin{table}[H]
\centering
\caption{RIPv2 与静态路由方案对比}
\label{tab:rip-static}
\begin{tabular}{|p{3cm}|p{5cm}|p{5cm}|}
\hline
\textbf{比较项} & \textbf{RIPv2 动态路由} & \textbf{静态路由} \\ \hline
配置复杂度 & 初始配置较简单，声明直连网段即可 & 每条目的网段都需要手工配置 \\ \hline
扩展性 & 新增网段后可自动传播 & 需要逐台设备补充路由 \\ \hline
故障恢复 & 链路变化后可重新收敛 & 需要人工调整下一跳 \\ \hline
资源消耗 & 周期性更新，占用少量带宽 & 几乎不占用协议带宽 \\ \hline
适用场景 & 小型和中型网络、教学实验 & 小规模固定拓扑、默认路由 \\ \hline
\end{tabular}
\end{table}

\subsubsection{路由收敛过程}

当分公司路由器启动后，会通过直连串行链路向核心路由器发送 RIPv2 更新报文。核心路由器学习到分公司 172.16.x.0/24 网段后，再将该信息通告给总部路由器和其他分公司路由器。总部路由器也会将 192.168.10.0/24 至 192.168.80.0/24 等网段通告给核心路由器，使分公司能够获得访问总部服务器区和各部门 VLAN 的路径。

为了避免 RIPv1 的有类汇总问题，本方案在所有 RIP 进程中配置 \texttt{no auto-summary}。该命令可以防止路由器在主类边界自动汇总网段，保证 192.168.x.0/24、172.16.x.0/24 和点到点 /30 网段能够按实际掩码传播。

\subsubsection{默认路由传播}

企业内网访问互联网时，需要将未知目的地址转发到 ISP。可以在 Core-Router 上配置默认路由指向 ISP，再通过 RIP 将默认路由下发给总部与分公司路由器。在 Packet Tracer 中也可以采用各路由器手工配置默认路由的方式，便于观察路径。

\begin{lstlisting}[caption={默认路由与 RIP 默认路由传播示意}, label={lst:default-route}]
! ---- Core-Router 上配置默认路由 ----
ip route 0.0.0.0 0.0.0.0 202.100.1.1

! ---- 在 RIP 中通告默认路由 ----
router rip
 version 2
 default-information originate
\end{lstlisting}

默认路由传播后，总部和分公司终端访问外部地址时，会先将数据包送至本地网关，再沿 RIP 学习到的默认路径到达 Core-Router，并通过 NAT/PAT 转换后进入 ISP 网络。

\subsection{VPN 安全机制深化}

VPN 是本方案区别于普通园区网设计的重要部分。企业分公司跨省部署，不能假设公网链路可信，因此需要通过 IPSec 为站点间通信提供机密性、完整性和身份认证。

\subsubsection{IPSec 工作阶段}

IPSec VPN 通常分为两个阶段：

\begin{enumerate}[label=(\arabic*), leftmargin=2em]
    \item \textbf{IKE Phase 1}：双方协商加密算法、散列算法、认证方式和 DH 密钥交换组，建立 ISAKMP 安全关联；
    \item \textbf{IKE Phase 2}：在 Phase 1 的安全通道内协商 IPSec 参数，建立用于实际业务数据加密的 IPSec SA。
\end{enumerate}

本方案采用 AES-256 作为加密算法，SHA 作为完整性校验算法，使用预共享密钥完成对等体身份认证。对于课程设计和 Packet Tracer 仿真而言，该配置足以体现 IPSec 的核心流程；在真实生产网络中，可进一步使用证书认证替代预共享密钥。

\subsubsection{感兴趣流量设计}

IPSec 并不是对接口上的所有流量都加密，而是通过 ACL 匹配“感兴趣流量”。例如总部 192.168.0.0/16 访问 Branch1 的 172.16.1.0/24 时触发 VPN 隧道，普通互联网访问流量则走 NAT 出口。这样可以避免将无关流量引入 VPN，提高链路利用效率。

需要注意的是，站点间 VPN 的 ACL 必须在两端保持镜像关系。总部侧写作 ``源为总部网段、目的为分公司网段''，分公司侧则写作 ``源为分公司网段、目的为总部网段''。如果两端 ACL 不匹配，即使 IKE Phase 1 成功，也可能无法建立 Phase 2 的 IPSec SA。

\subsection{ACL 策略设计深化}

ACL 访问控制的关键不只是写出 deny 和 permit 规则，还要考虑规则顺序、应用方向和部署位置。本方案遵循“靠近源端阻断非法流量，靠近目的端保护关键服务器”的原则。

\subsubsection{规则顺序}

Cisco ACL 按从上到下的顺序匹配，命中第一条规则后立即停止。因此，拒绝规则必须写在允许全部流量之前。若将 \texttt{permit ip any any} 放在 deny 之前，后续拒绝规则将永远不会生效。

\begin{lstlisting}[caption={ACL 规则顺序示例}, label={lst:acl-order}]
! 正确顺序：先拒绝，再允许其他流量
access-list 100 deny ip 192.168.10.0 0.0.0.255 192.168.20.0 0.0.0.255
access-list 100 permit ip any any

! 错误示例：第一条 permit 已匹配全部流量，deny 不会生效
access-list 100 permit ip any any
access-list 100 deny ip 192.168.10.0 0.0.0.255 192.168.20.0 0.0.0.255
\end{lstlisting}

\subsubsection{应用方向}

ACL 可以应用在接口入方向或出方向。对于市场部访问财务部的限制，将 ACL 应用在 VLAN 10 入方向，可以在流量刚进入三层网关时即被阻断，减少核心层不必要转发。对于 FTP 服务器保护，将 ACL 应用在服务器区出方向或入口方向，需要结合拓扑中服务器区网关位置确定。

\begin{tabular}{|p{3cm}|p{4cm}|p{3cm}|p{4cm}|}

\subsection{服务器区与 DMZ 设计讨论}

本次 Packet Tracer 方案中，Web、FTP、Email、DNS/DHCP 等服务统一部署在总部服务器区 VLAN 80。对于课程设计而言，该方式结构清晰，便于验证服务连通性和 ACL 控制。但在真实企业环境中，对外服务通常建议部署在 DMZ 区，与内部 OA、DHCP 和数据库等系统隔离。

\subsubsection{当前服务器区设计}

当前设计的优点是部署成本低、管理简单、配置量适中。所有服务器位于同一个 VLAN，网关统一为 192.168.80.1，部门终端通过三层交换访问服务器区，外部访问通过边界策略控制。

当前设计的不足是安全边界较集中。如果 Web 服务因漏洞被攻击，攻击者可能尝试横向扫描同一服务器区内的其他服务。因此，本方案在安全展望中建议后续增加独立防火墙和 DMZ。

\subsubsection{可升级 DMZ 方案}

若进行生产化升级，可以将服务器区拆分为三个区域：

\begin{itemize}
    \item \textbf{DMZ 区}：部署企业门户 Web、对外邮件网关等允许互联网访问的服务；
    \item \textbf{内部服务区}：部署 OA、DHCP、DNS 内部解析、文件服务等仅内网访问的服务；
    \item \textbf{管理区}：部署日志服务器、网络管理系统、备份服务器，仅允许管理员访问。
\end{itemize}

\subsection{可靠性设计}

可靠性设计需要从设备、链路、协议和管理四个层面考虑。Packet Tracer 仿真环境中设备数量有限，但设计思路仍应体现工程可落地性。

\subsubsection{设备可靠性}

核心路由器和核心交换机是当前拓扑中的关键节点。若 Core-Router 故障，总部、分公司和互联网之间的通信都会受到影响；若 HQ-Core-SW 故障，总部各 VLAN 和服务器区通信会中断。因此在真实部署中应考虑双核心设备冗余。

\subsubsection{链路可靠性}

总部到 ISP、总部到分公司链路可以采用主备线路。主线路可选择专线或企业宽带，备线路可选择 4G/5G CPE 或第二运营商宽带。通过浮动静态路由或动态路由度量值调整，可以实现故障时自动切换。

\subsubsection{协议可靠性}

二层网络中启用 STP 避免环路；三层网络中启用动态路由自动适应链路变化；VPN 通过 SA 生命周期定期重协商密钥，减少长期使用同一密钥带来的风险。对于关键服务器，可通过定期备份、双网卡绑定和服务监控提高可用性。

\subsection{实施步骤与上线流程}

网络工程实施不能只依赖最终配置，还需要明确部署顺序。合理的上线流程可以降低故障范围，便于分阶段验证。本方案在 Packet Tracer 中按“基础连通、路由互通、业务服务、安全策略、VPN 接入、综合验证”的顺序实施。

\begin{enumerate}[label=(\arabic*), leftmargin=2em]
    \item \textbf{设备摆放与连线}：在 Packet Tracer 中添加核心路由器、总部路由器、ISP 路由器、分公司路由器、核心交换机、接入交换机和服务器，并按照拓扑图连接链路；
    \item \textbf{基础接口配置}：为各路由器接口、交换机 SVI、服务器和终端配置 IP 地址，确保所有直连链路状态为 up；
    \item \textbf{VLAN 与 Trunk 配置}：在总部核心交换机上创建 VLAN 10--80，将接入端口划入对应 VLAN，并配置上行 Trunk；
    \item \textbf{动态路由配置}：在总部、核心、ISP 和分公司路由器上启用 RIPv2，关闭自动汇总，检查路由表是否学习到远端网段；
    \item \textbf{DHCP 与 DNS 配置}：配置 DHCP 地址池和 DNS 解析记录，验证终端能够自动获得地址并解析域名；
    \item \textbf{NAT 出口配置}：配置内外网接口、NAT ACL 和 PAT 规则，验证内网终端可访问外网；
    \item \textbf{ACL 安全策略配置}：逐项添加部门访问限制和服务器访问限制，每添加一条规则后立即测试；
    \item \textbf{IPSec VPN 配置}：配置 IKE、转换集、加密 ACL 和 crypto map，验证站点间隧道建立；
    \item \textbf{远程访问 VPN 配置}：配置 VPN 用户、地址池和远程接入策略，验证外部 PC 可拨入企业内网；
    \item \textbf{综合验收测试}：按照测试用例逐项记录结果，形成测试截图和测试表格。
\end{enumerate}

\subsection{常见故障与排查方法}

网络配置过程中常见问题包括接口未启用、网关错误、VLAN 划分错误、RIP 未学习路由、ACL 误拦截、NAT 方向配置错误和 VPN 两端参数不一致。排错时应遵循从物理层到应用层的顺序，逐层定位。

\subsubsection{连通性排查顺序}

\begin{enumerate}[label=(\arabic*), leftmargin=2em]
    \item 检查终端 IP、子网掩码、默认网关和 DNS 是否正确；
    \item Ping 本机网关，确认同 VLAN 到网关的二层与三层连通；
    \item Ping 同一设备的远端接口，确认路由器或三层交换机转发正常；
    \item 查看路由表，确认是否存在到目标网段的路由；
    \item 暂时查看 ACL 命中情况，确认是否被访问控制规则拦截；
    \item 对互联网访问问题查看 NAT 转换表；
    \item 对 VPN 问题查看 IKE 和 IPSec SA 状态；
    \item 最后检查应用服务端口是否开启，例如 HTTP、FTP、SMTP、POP3。
\end{enumerate}

\subsection{运行维护方案}

网络上线后，维护工作主要包括日常巡检、故障处理、配置备份、安全审计和容量评估。良好的运维制度能够减少人为误操作，并在出现故障时缩短恢复时间。

\subsubsection{日常巡检内容}

\begin{itemize}
    \item 每日检查核心路由器、核心交换机和服务器运行状态；
    \item 每日检查关键链路接口状态和错误包计数；
    \item 每周检查 DHCP 地址池使用率，避免地址耗尽；
    \item 每周检查 NAT 转换、VPN 连接和路由表变化；
    \item 每月备份所有关键设备配置；
    \item 每月复核 ACL 规则，删除不再使用的临时放行策略；
    \item 每季度进行一次故障演练，包括出口中断、VPN 中断和服务器服务停止等场景。
\end{itemize}

\subsubsection{变更管理}

网络变更应遵循申请、评估、实施、验证、回退和归档流程。尤其是 ACL、NAT、VPN 和路由相关变更，一条错误规则可能导致大范围中断，因此必须在低峰期执行，并提前准备回退命令。

\begin{enumerate}[label=(\arabic*), leftmargin=2em]
    \item \textbf{变更申请}：说明变更目的、涉及设备、涉及业务和预期影响；
    \item \textbf{风险评估}：判断是否影响财务、OA、邮件、互联网出口和分公司访问；
    \item \textbf{实施准备}：备份当前配置，准备变更命令和回退命令；
    \item \textbf{窗口实施}：在业务低峰期执行，实时观察接口、路由和业务状态；
    \item \textbf{结果验证}：按测试用例验证允许流量和禁止流量；
    \item \textbf{归档记录}：保存变更前后配置、测试结果和负责人信息。
\end{enumerate}

\subsection{网络安全运维建议}

安全设计不仅体现在初始配置，也依赖持续运维。本方案建议在后续真实部署中补充以下措施：

\begin{itemize}
    \item 设备管理账号采用强密码，并定期更换；
    \item 关闭未使用端口，将空闲交换机端口划入隔离 VLAN；
    \item 管理平面限制来源地址，只允许管理员网段登录设备；
    \item 启用日志记录，将关键设备日志发送到集中日志服务器；
    \item 对远程 VPN 用户实行账号实名制，离职人员及时禁用账号；
    \item 对服务器区进行定期漏洞扫描，及时修补 Web、FTP、Email 服务漏洞；
    \item 定期检查 ACL 命中计数，发现异常访问趋势及时分析；
    \item 对重要配置文件进行离线备份，避免单点存储损坏。
\end{itemize}

\subsection{预算测算依据}

\subsubsection{接入端口测算}

1000 台 PC，每台接入交换机（Cisco 2960）提供 48 个端口，则：
\[
\text{所需交换机数量} = \lceil 1000 / 48 \rceil = \lceil 20.83 \rceil = 21 \text{ 台}
\]

考虑 3 个部门接入交换机 + 1 台服务器交换机共 4 台覆盖总部核心接入，其余终端通过分公司交换机（3 台 1960-24TT，每台 24 口）承载。

\subsubsection{核心带宽测算}

假设单用户平均带宽需求为 20 Mbps，并发率为 30\%，则核心交换机上行带宽需求为：
\[
\text{上行带宽} = 1000 \times 20\text{ Mbps} \times 30\% = 6000\text{ Mbps} = 6\text{ Gbps}
\]

核心交换机（2560-24PS）提供 24 个千兆端口，支持线速转发，满足带宽需求。

\subsection{详细验收测试方案}

\subsubsection{测试环境}

测试平台为 Cisco Packet Tracer 8.x，使用的主要设备包括 Cisco 2811 路由器、Cisco 2560-24PS 核心交换机、Cisco 2960 接入交换机、Cisco 1960-24TT 分公司交换机、Server-PT 服务器和 PC-PT 终端。测试拓扑文件为 \texttt{计算机网络课程设计\_题目二\_拓扑图\_V2.pkt}。

    \item 总部财务部 PC：用于验证高安全部门能够访问必要业务服务；
    \item 总部研发部 PC：用于验证跨 VLAN 访问服务器与分公司互通；
    \item 分公司 PC：用于验证站点间 VPN 和 RIPv2 跨站点路由；

\subsection{性能与容量验证}

Packet Tracer 无法完全模拟真实企业网络中的高并发流量，但可以从地址容量、端口容量、链路层级和路由规模四个方面进行合理性验证。

\subsubsection{地址容量}

总部每个部门采用 /24 子网，单个 VLAN 可容纳 254 个可用主机地址。对于大多数部门，该容量可以满足当前终端规模；研发部如超过 254 台终端，可通过新增研发二级 VLAN 进行扩展。分公司各使用 172.16.x.0/24 网段，满足每个分公司数十到两百台终端的规模需求。

\subsubsection{端口容量}

课程设计拓扑中为了便于展示，使用少量 PC 代表各部门终端。在真实部署中，1000 台终端需要约 21 台 48 口接入交换机，另需预留服务器、打印机、无线 AP、会议终端等端口。因此工程预算中需要考虑接入交换机扩容和弱电间布线空间。

\subsubsection{路由规模}

当前路由表包含总部 8 个 VLAN 网段、3 个分公司网段、若干点到点链路网段和公网互联地址。该规模远低于 RIPv2 可承载的复杂度，路由收敛与维护压力较小。由于采用 Hub-and-Spoke 架构，新增分公司时主要增加一条点到点链路和一个 172.16.x.0/24 网段，对原有拓扑影响较小。

\subsection{应急恢复预案}

网络故障发生时，处理目标是先恢复关键业务，再分析根因。企业关键业务包括 OA、邮件、服务器区访问、互联网出口、总部与分公司互联和远程 VPN 接入。应急恢复预案应包含故障识别、影响范围判断、临时恢复、根因分析和复盘改进。

\subsubsection{核心设备故障}

若 Core-Router 故障，首先确认设备电源、接口状态和配置是否正常。如果是配置误操作导致，可通过最近一次备份恢复；如果是设备硬件故障，真实环境中应切换到备用核心路由器。Packet Tracer 仿真中可通过重新加载保存的拓扑文件恢复实验状态。

\subsubsection{出口访问故障}

若内网无法访问互联网，应按顺序检查终端网关、核心路由默认路由、NAT inside/outside 标记、NAT ACL、ISP 侧接口和外部服务器状态。若 NAT 转换表没有记录，优先检查 NAT ACL 是否匹配内网源地址；若有转换记录但外部不通，优先检查默认路由和 ISP 返回路径。

\subsubsection{VPN 故障}

VPN 故障通常来自对等体地址错误、预共享密钥不一致、IKE 策略不匹配、感兴趣流量 ACL 不镜像或接口 crypto map 未应用。排查时应先通过普通 ping 确认两端公网接口可达，再查看 IKE Phase 1 状态，最后查看 IPSec SA 是否产生加密和解密计数。

\subsection{Packet Tracer 仿真的局限性}

Packet Tracer 非常适合课程设计和网络基础实验，但它并不能完全等同于真实生产网络。首先，Packet Tracer 对部分 Cisco IOS 命令支持有限，一些真实设备上的高级特性可能无法完整模拟。其次，仿真环境中的链路延迟、丢包、吞吐量和设备性能并不等同于真实硬件。再次，安全攻击、日志审计、漏洞扫描和大规模并发访问也无法完全在 Packet Tracer 中重现。

因此，本报告中的设计结论适用于课程设计验证和中小企业网络规划原型。若进入真实部署阶段，还需要结合实际设备型号、运营商链路、楼宇布线、服务器系统、安全合规要求和预算进行二次深化设计。尤其是防火墙、DMZ、双核心冗余、日志审计和备份恢复，应在生产环境中重点补充。

\section{总结与展望}

\subsection{项目总结}

本方案采用 Cisco Packet Tracer 平台，基于 \textbf{Hub-and-Spoke} 网络拓扑架构，完成了中小企业网络规划与设计。方案综合运用了以下关键网络技术：

\begin{enumerate}[label=(\arabic*), leftmargin=2em]
    \item \textbf{VLAN 逻辑隔离}：将 7 个部门和服务器区划分为 8 个独立广播域，实现二层隔离和三层互通；
    \item \textbf{RIPv2 动态路由}：替代旧版方案中的 OSPF，使用更简洁的距离矢量路由协议实现全网路由自动学习；
    \item \textbf{ACL 访问控制}：实现部门间精细化访问控制和 FTP 服务的内部限用策略；
    \item \textbf{NAT 地址转换}：通过 PAT 实现内网终端共享公网 IP 访问互联网；
    \item \textbf{IPSec VPN}：实现总部与三个分公司的站点到站点加密通信，以及远程办公人员的安全接入；
    \item \textbf{DHCP 自动编址}：实现终端 IP 地址的自动分配和管理；
    \item \textbf{STP 环路防护}：确保二层网络的稳定运行。
\end{enumerate}

\subsection{方案特色}

与旧版方案相比，本 V2 方案具有以下改进和特色：

\begin{itemize}
    \item \textbf{更清晰的层次结构}：采用 Hub-and-Spoke 架构，核心路由器作为全网枢纽，层次分明，便于管理和故障排查；
    \item \textbf{真实的设备选型}：使用 Cisco Packet Tracer 中具体可仿真的设备型号（2811 路由器、2560-24PS 交换机、2960 交换机、1960-24TT 交换机）；
    \item \textbf{双重 VPN 架构}：同时支持站点到站点 VPN 和远程访问 VPN，满足更多业务场景；
    \item \textbf{服务整合}：将 DNS 与 DHCP 整合、FTP 与 Email 整合，减少服务器数量，降低运维成本；
    \item \textbf{更全面的测试覆盖}：包含 13 项功能测试，覆盖 VLAN、ACL、DHCP、NAT、FTP、Email、VPN 等全部功能点；
    \item \textbf{实用优先的设计理念}：RIPv2 相比 OSPF 在小网络中配置更简单，更适合中小企业的实际运维能力。
\end{itemize}

\subsection{未来展望}

本方案虽然已满足当前需求，但仍可在以下方面进行改进和扩展：

\begin{enumerate}[label=(\arabic*), leftmargin=2em]
    \item \textbf{高可用性}：引入 HSRP/VRRP 网关冗余协议，部署双核心路由器和双核心交换机，消除单点故障；
    \item \textbf{安全增强}：部署独立的防火墙设备（如 Cisco ASA），在 DMZ 区部署对外服务器，实现更严格的安全隔离；
    \item \textbf{QoS 质量保证}：引入 QoS 策略，为 VoIP、视频会议等实时业务提供带宽保障；
    \item \textbf{无线网络覆盖}：增加无线 AP 和无线控制器（WLC），支持移动办公终端接入；
    \item \textbf{IPv6 支持}：引入 IPv6 双栈部署，为未来网络演进做好准备；
    \item \textbf{网络监控}：部署 SNMP 网络管理系统（如 Cisco Prime），实现全网设备的集中监控和故障告警。
\end{enumerate}
